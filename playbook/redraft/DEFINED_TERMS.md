# Drafting Standard & Defined-Terms Glossary — Playbook v3.1 pass

Confidential & Legally Privileged. This is the consistency backbone for the v3.1 redraft of all
clause templates. Every template is normalised to these conventions. No new substance is added beyond
what the v3.0 master already sets out.

## Conventions
- **Defined terms**: Capitalised, **no brackets** (e.g. *the Company, the Counterparty, the Services*).
  Brackets are reserved for **fill-ins** to be completed at drafting (e.g. `[USD X]`, `[12] months`,
  `[●]`, `[date]`).
- **Parties**: *the Company* (the protected principal) and *the Counterparty*.
- **Cross-references**: `Clause [●] (Title)` — never hard-coded numbers (e.g. not "Clause 4.1").
- **Spelling**: UK / Commonwealth English (Singapore-law context): *authorise, capitalise, organisation,
  licence* (noun) / *license* (verb), *fulfil*.
- **Obligations / prohibitions**: *shall* (obligation), *may* (discretion), *shall not* / *must not*
  (prohibition). No contractions. Active voice. Present tense for operative provisions.
- **Numbering**: first level `(a) (b) (c)`; second level `(i) (ii) (iii)`. Lead-in bold heading, e.g.
  **Limitation of Liability.**
- **"Including"**: construed as non-limiting per the Interpretation clause; thereafter plain *including*.
- **Templates vs notes**: a *template* is operative, paste-ready clause text. Conditional guidance
  ("accept only if…", "for low-value deals…") is **not** clause text and is moved to *Notes for Counsel*.

## Canonical defined terms (use exactly; do not invent variants)
| Term | Use |
|---|---|
| this Agreement | the contract as a whole, incl. Schedules |
| the Effective Date | commencement date |
| the Company | the protected principal (deployment-branded via config; `[Company]` placeholder in template text) |
| the Counterparty | the other party |
| the Services | services to be provided |
| the Deliverables | deliverables to be provided |
| the Platform | the Company's platform/systems |
| the Fees | amounts payable |
| Applicable Law | all applicable laws (replaces "Applicable Laws"/"Regulatory Requirements" where general) |
| Regulatory Requirements | requirements of a Regulator, where specifically regulatory |
| Personal Data | as defined under applicable data-protection law |
| a Data Breach | personal-data / security breach |
| Intellectual Property Rights | IP rights |
| Confidential Information | confidential information |
| a Statement of Work / an Order Form | ordering documents |
| the Documentation | specifications/manuals |
| the Service Levels / the Specifications / the Acceptance Criteria | performance/quality criteria |
| a Schedule | schedule/annex to this Agreement |
| the Longstop Date | backstop date for conditions |
| Customer Assets | customer funds/assets (digital assets, gold, etc.) |

## Tiering (unchanged from v3.0)
Baseline (balanced) · Buy-Side (maximum Company protection) · Sell-Side (Company liability-controlled)
· Acceptable Fallback (negotiated minimum). Red Flags and Usage Notes are counsel guidance, not clauses.
